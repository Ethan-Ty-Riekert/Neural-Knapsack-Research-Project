# Portfolio artefacts -- Neural-Knapsack Research Project

A curated, diverse selection of work samples from this project, for the "Selection of
Artefacts" section of the yearly portfolio. Everything here is real project output (either
generated directly from recorded results, or copied unedited from the codebase) -- nothing
here is fabricated for the portfolio.

## figures/ -- data visualisation

- **`offline_tardiness_comparison.png`** -- every offline-case method this project tested,
  one chart, log scale. Shows the full arc: historic PPO (~1310 tardiness, statistically
  indistinguishable from ignoring deadlines) down to Option 1's 11.00, three units off the
  CP-SAT/LST proven-optimal floor of 8.00. Demonstrates: result synthesis across a long
  experimental campaign, log-scale chart design for a wide dynamic range.
- **`online_more_training_hurts.png`** -- a genuine negative result: more training
  consistently regresses the online policy, confirmed three independent times. Demonstrates:
  honest reporting of an unresolved finding, not just successes.
- **`rcpo_timeline.png`** -- a dual-axis chart showing how a "best-ever" result was
  diagnosed as reward hacking (near-zero tardiness bought by abandoning half the jobs), and
  how the subsequent fix didn't survive a 3-seed rigor check. Demonstrates: statistical
  rigor and willingness to revise an earlier positive claim.
- **`example_machine_utilisation_ppo.png`**, **`example_eval_total_tardiness.png`** --
  unedited plots auto-generated by the project's own evaluation pipeline
  (`Code/evaluation/eval_rl_agent.py`), included to show the actual tooling output, not just
  hand-built summary charts.

## data/

- **`key_results_excerpt.csv`** -- a filtered slice of the project's full experiment
  tracking file (`rl_training/results/eval_results.csv`, ~99 rows), showing every Options
  1-4 evaluation recorded against every heuristic baseline. Demonstrates: structured,
  reproducible experiment logging (every run auto-appends here via
  `Code/utils/results_log.py`), not just numbers pasted into a log by hand.

## code-samples/

- **`rule_selection_gym_wrapper.py`** -- the actual implementation of Option 1, the
  project's best-performing design: a Gym wrapper that lets an RL policy select which
  classical dispatching rule to apply each tick, rather than learning scheduling from a raw
  job/machine action space. Demonstrates: composition-over-inheritance design (wraps an
  existing environment rather than subclassing it), integrating RL with classical
  heuristics.
- **`priority_rules.py`** -- the classical scheduling heuristics (EDF, SPT, LST, WSPT, ATC)
  used as both baselines and, via the wrapper above, as the RL agent's own action space.
  Demonstrates: correct implementation of literature-grounded scheduling rules (e.g. the ATC
  composite priority index, Vepsalainen & Morton 1987).

## Why this counts as professional development, not just project output

- The RCPO and online-training figures are both *negative* results, kept and reported
  rather than discarded -- an explicit project convention (`training-log.md` is append-only;
  a wrong conclusion gets a new dated entry, not a rewrite).
- The results CSV shows a project run with the same experiment-tracking discipline expected
  in industry ML work (every run logged with its comparison baseline, seed, and protocol),
  not ad hoc numbers copied from a terminal.
- The code samples reflect a "subclass/wrap, don't modify" convention applied consistently
  across the codebase, adopted specifically to keep the offline and online cases correct
  simultaneously without duplicating logic.
