# Development guide

Working notes for developing and running experiments in this repository. The project overview,
reproduction steps and results are in the top-level `README.md`.

## Branches

- `main` -- reviewed, released states only. Papers cite a **tag** on `main` (e.g. `paper-2026-10`),
  never the moving branch.
- `dev` -- all day-to-day work and experiment campaigns. Released to `main` when a state is finished.
- `archive/<name>` tags -- the former experiment branches (`Fixing_Evaluation`, `MathRevision`,
  `autonomous-overnight-2026-08-28`, `rcpo-constrained-optimization`, `legacy-reward-v1`,
  `objective-redesign`), all fully merged; kept as tags so their history stays reachable.

## Releasing to main

```
bash tools/release.sh                 # merge dev into main, without the private working files
bash tools/release.sh paper-2026-10   # ... and tag the release that a paper cites
```

The excluded paths (the author's notes and AI-assistant working files) are listed once, in
`tools/release.sh`. The script works in a separate git worktree, so a campaign running from the
working directory is unaffected. Files excluded from `main` remain in `dev` and in the git history.

## Running modules

Run everything from the repository root, as modules (`python -m Code....`), not as script files:
direct execution breaks the `Code.*` absolute imports.

```
python run.py                  # interactive menu
python run.py --list           # variants, presets, methods
python run.py --variant v1_legacy_reward --preset off_c_15 --method EDF
python run.py --experiment experiments/pso_vs_edf_off_c_15.yaml

# v2 RL: train (parallel envs, seeded), then evaluate / compare against heuristics
python run.py --variant v2_objectives --preset on_rho095 --method rl-train:1 --n-envs 4 --seed 0 \
    --rule-placements FirstFit,Consolidate --timesteps 300000 --checkpoint-tag v2_on_rho095_o1c_s0
python run.py --variant v2_objectives --preset on_rho095 \
    --method "rl-eval:1:v2_on_rho095_o1c_s0,EDF+Consolidate,RandomRule+FirstFitConsolidate"
```

Trained RL models save a sidecar `<model>.json` with every environment and observation option they
were trained with, so `rl-eval:<option>:<tag>` rebuilds the matching environment from the tag alone
(`GymSchedulingEnv.apply_options`). Tag convention and modifier letters: `tools/campaign/README.md`.

Heuristic / PSO / CP-SAT runs are saved to `Results/<variant>/runs/<timestamp>_<preset>_<method>/`
(`run.json` with git commit, machine, full config and metrics, plus `per_instance.csv`).

## Long training campaigns

`tools/campaign/` holds a load-aware job queue (keeps CPU at or below a target, Below Normal priority),
an automatic test-set evaluator and a CPU watchdog; see `tools/campaign/README.md`. The v2/v3
hyperparameter studies are generated by `python -m Code.methods.rl.training.tune_optuna_v2 jobs`.

## GPU training (AMD, DirectML)

The main environment is CPU-only. A separate environment beside the repository holds a DirectML build of
PyTorch (Python 3.11; torch-directml supports up to 3.12), so GPU work can never break the CPU campaign:

```
py -3.11 -m venv ../nk-gpu
../nk-gpu/Scripts/python.exe -m pip install torch-directml stable_baselines3==2.8.0 sb3_contrib==2.8.0     gymnasium==1.2.3 "numpy<2.5" optuna psutil pandas matplotlib pyyaml tensorboard ortools==9.15.6755
```

`--device dml:1` (or env `NK_TORCH_DEVICE=dml:1`) puts the networks on DirectML device 1 (the RX 7900 XT; device 0
is the integrated GPU). Two DirectML issues are handled in `train_action_space_variant.py`: the optimizer is
rebuilt after the policy moves to the device (`rebind_optimizer`; otherwise it updates stale CPU copies and nothing
learns), and Categorical.log_prob is computed without a scatter (`_directml_safe_categorical`, identical values).
Saved models are always CPU models, so evaluation runs in the main environment. The environments still step on the
CPU, so the GPU mainly speeds up network updates (online PPO with default settings: ~3-4x).

A second queue runner feeds the GPU:

```
python tools/campaign/queue_runner.py --name gpu --queue queue_gpu.txt --settings runner_settings_gpu.json     --python ../../nk-gpu/Scripts/python.exe --stay
```

## Two machines: artefact storage

Set `NK_ARTIFACTS_DIR` to a cloud-synced folder and (optionally) `NK_MACHINE` to a machine name;
generated artefacts then go to `NK_ARTIFACTS_DIR/<machine>/` instead of `rl_training/`. Each machine
writes only its own subfolder (sync tools corrupt `optuna.db` and fork appended CSVs otherwise).
Unset = the default `rl_training/` (gitignored).

## Research records

- `Future/research/training-log.md` -- chronological experiment log (newest first, append-only).
- `Future/research/YYYY-MM-DD-<topic>.md` -- dated design and investigation write-ups.
- `Future/research/references.bib` -- every source consulted.
- `PROGRESS.md` -- narrative history of the project.
